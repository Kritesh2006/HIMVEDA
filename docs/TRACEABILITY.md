# Traceability

## Batch codes

```
HIM-26-KTM-00482
 │   │   │    └─ sequence, per centre per year (5 digits)
 │   │   └────── originating collection-centre code (3 letters)
 │   └────────── year the batch was formed
 └────────────── HIMVEDA
```

Generated by `nextBatchCode()` when a batch is formed in Studio. They are permanent: they are printed on packs, stored on order lines, and served at `/trace/<code>`. The lookup form normalises input, so `him 26 ktm 482` becomes `HIM-26-KTM-00482`.

## The chain

```
Farmer / producer ─► Collection centre ─► Inspection ─► Procurement ─► Batch ─► Processing ─► Packed ─► Market ─► Order
   farmers/farms     collection_receipts   inspections   procurements   batches   processing_runs  inventory   products   orders
```

In Studio:

1. **Farmers**: register a producer (private name and phone, district, approximate plot location, optional consented public name).
2. **Collection → Record a delivery**: gross and tare weight produce a numbered receipt.
3. **Inspect**: grade, moisture, foreign matter, accepted kg, and a pass, hold or fail result.
4. **Procure**: accepted kg × the centre's approved rate for that commodity, adjusted by grade. This creates a pending producer payment.
5. **Traceability → Form a batch**: select procured receipts from one centre. The code is issued and origin, collection and verification events are generated.
6. **Log processing** runs, **record checks**, **add events** (packed, available), then **publish the trace page**.
7. Link the batch to a **product**. The product page then shows "This stock comes from batch …".

## What is public

| Shown | How |
| --- | --- |
| Origin district | from receipts |
| Approximate origin | mean of farm coordinates, **rounded to 0.1° (~10 km)** |
| Number of producers | count only |
| Collection centre | only if the centre is marked public |
| Weights, moisture, grade, yields, pack count | from events and batch |
| Checks | only `is_public` tests, with who performed them; a report link only if a document is attached |
| Producer name | only with `publish_consent` and a `public_name` |

## What is never public

Producer names without consent, phone numbers, exact coordinates, receipt-level data, procurement rates, amounts paid, payment references, private event notes, staff names and editor identities. The public view model (`getPublicTrace`) is an explicit allow-list. Fields are copied in one by one, never spread from database rows.

## Honesty rules

- A batch's page says "No laboratory certificate is on file for this batch" unless a real report is attached.
- Demonstration batches display "Sample data".
- Events are written by people in Studio and attributed in the audit log. The public page is a view of operating records, not copy written after the fact.
